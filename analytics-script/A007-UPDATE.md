# A007 — VI/d 및 일회용 리더 보고서

## 적용 파일과 실행 함수

1. 분석 Apps Script의 `Code.gs`, `Layout.gs`를 전체 교체합니다. 운영 프로젝트를 수정하지 않습니다.
2. 새 스크립트 파일 `LeadershipReport.gs`를 만들고 동봉 내용을 붙여넣습니다.
3. 일반 `refreshListingAnalytics` 실행: 크롤링 효과 탭의 시간당 표가 없어지고 VI/d·리스팅 용어가 적용됩니다.
4. **`buildCrawlerHubLeadershipReport`를 별도로 한 번 실행**: `Crawler Hub 리더 보고` 탭 하나를 생성합니다.

보고서는 `refreshListingAnalytics`, 메뉴 자동 갱신, 일일 트리거에 연결하지 않았습니다. 일반 새로고침은 보고서 탭을 변경하지 않습니다. 명시적으로 별도 함수를 다시 실행하면 같은 이름의 보고서만 덮어씁니다. 같은 이름의 다른 내용이 있으면 보존을 위해 중단합니다.

신규 권한/운영 배포/트리거 재설치/setup은 필요하지 않습니다. 기존 분석 파일 CONFIG와 근무비율을 그대로 읽습니다. `투입 계획 설정`의 예전 등록·환산 단위 키도 읽을 수 있도록 호환합니다.

## VI/d

`d = 작업자별 고유 기록일 × CONFIG 근무비율`

`VI/d = 완료 VI ÷ d`

0.5 근무자의 10기록일은 5d입니다. 시간은 사용하지 않습니다. 단위는 보정 근무일이며 실제 출근일이나 8시간 환산 노동시간은 아닙니다. 비율 미설정은 1입니다. 크롤링 효과 탭의 기존 VI/h 표는 제거했습니다. 다른 탭의 과거 시간 기반 표는 참고로 유지합니다. 화면 용어는 리스팅을 사용합니다.

## 리더 보고서 구성

- 9·10월 전체, 11월 기준일까지의 팀 물량·VI/d·크롤링 비중·참여 인원
- 기간 차이를 확인할 수 있도록 각 월 1~기준일의 리스팅 VI/d
- 같은 참여 집단의 10→11월 변화와 크롤링/비크롤링 효과 배수. 개인별 수치·이름·순위는 표시하지 않음
- 크롤링과 리스팅을 합친 총 관측 d와 VI/d. 같은 사람·같은 날짜는 두 단계에 있어도 한 번만 계산
- 같은 1,000 VI 기준 기록 d 및 전체 완료 요청의 홀드 제외 처리기간
- 개선/우위를 미리 정하지 않는 자동 해석과 기록 누락·비교 범위 각주

`CRAWLER_HUB_REPORT_OPTIONS.asOf`는 이번 일회용 보고서의 기준일 `2026-11-20`입니다. 필요하면 실행 전 이 날짜를 실제 보고 기준일로 수정하세요. 2026년 11월 안에서만 지원하며, REQUESTS는 실행 시점의 현재 메타데이터입니다. 과거 날짜의 상태를 복원하는 기능은 아닙니다.

보고서는 12열, 약 45행의 한 화면 구성입니다. 인쇄 시 A1:L45를 선택하고 가로 방향·한 페이지 맞춤을 사용합니다. 기존 결과 탭을 여러 개 보여줄 필요 없이 이 탭만 제시할 수 있습니다.

## 비교와 한계

개별 크롤링 작업자 간 비교는 하지 않습니다. 10월 전담 인력과 11월 인력 확대는 월별 참여 인원 및 d로 분리합니다. 동일 참여 집단 지표는 두 달 모두 유효 자료가 있는 인원들의 월 변화 중앙값만 집계합니다. 크롤링 효과 배수는 같은 날 두 방식을 섞은 리스팅 기록일을 제외합니다.

크롤링 VI의 월은 해당 요청·크롤링 작업자의 마지막 CRAWL 기록월로 추정합니다. 완료일은 사용하지 않습니다. 현재 Total VI와 CRAWL_COMPLETED를 사용하므로 당시 제출 물량·상태와 다를 수 있습니다.

과거 백업은 CRAWL을 장기 집계에 남기지 않아 준비 일수가 빠질 수 있습니다. 연결률·분류 확인 비중·누락 VI를 함께 표시합니다. 필수 연결이 불완전하면 총 투입 VI/d의 월간 배수 및 1,000 VI 비용 비교는 확정 수치처럼 제시하지 않습니다.

허브 사용 여부, 실제 도입일, 당시 난이도는 원본에 별도 필드가 없습니다. 보고서는 허브 활용 확대 시기의 관측 변화를 보여주며, 인력 증가·업무 구성과 독립된 인과 효과를 확정하지 않습니다. 실제 회사 데이터로 함수를 실행한 뒤 표본과 결과를 확인해야 합니다.
