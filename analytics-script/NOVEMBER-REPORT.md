# 11월 보고 — 수치 중심 일회용 업데이트

분석 Apps Script의 기존 **LeadershipReport.gs만 전체 교체**한 뒤 **buildNovemberReport**를 실행합니다. 이전 함수 buildCrawlerHubLeadershipReport도 같은 함수를 호출하므로 계속 사용할 수 있습니다. 일반 refreshListingAnalytics, 트리거, 운영 코드는 변경하지 않습니다.

기존 자동 생성 보고서 탭은 **11월 보고**로 이름을 바꾸고 갱신합니다. 동일 이름의 사용자 작성 탭은 덮어쓰지 않습니다. 보고서는 별도 함수를 실행할 때만 갱신됩니다. 인쇄는 A1:L45 선택 → 가로 → 한 페이지 맞춤을 사용합니다.

## 변경한 집계

- CRAWL 세션이 있으면 해당 요청·크롤링 작업자의 마지막 세션 월을 사용합니다.
- 세션이 없으면 **REQUESTS Started At** 날짜의 월로 귀속합니다. Requested At이나 크롤링 완료일이 아닙니다.
- Started At로 귀속한 요청 수·VI를 따로 보존하며, 월별 크롤링 VI에 포함합니다. 시작일은 귀속월만 보완합니다. 크롤링 작업일·시간을 새로 생성하지 않습니다.
- 과거 크롤링 d가 복원되지 않은 월의 총 투입 생산성은 미복원으로 표시합니다. 리스팅 VI/d, 크롤링량·비중, 동일 집단 변화, 사례 배수는 유효 기록에서 계산합니다.

## 9월 기간

기본 septemberStart는 AUTO입니다. 유효 VI 기록의 일별 참여 인원만 보고, **7개 달력일 안에 3일 이상 기록 + 해당 기록일의 평균 참여 인원이 10월 일별 참여 인원 중앙값의 50% 이상**인 첫 관측 날짜를 선택합니다. VI 크기·효율 배수는 시작일 선택에 사용하지 않습니다.

조건에 맞는 구간이 없으면 첫 유효 기록부터 참고로 표시하고, 9월 데이터가 없으면 없음으로 표시합니다. 이는 기록이 완전해진 실제 전환일을 확정하는 방법은 아닙니다. 실행 결과의 시작일을 확인하세요. 정확한 전환일이 확인되면 파일 상단 septemberStart를 예를 들어 '2026-09-16'으로 지정할 수 있습니다. 선택일 전 9월 실적은 이 보고서에서 모두 제외합니다.

## 숫자 구성

- 상단: 11월 리스팅 완료 VI, 10월 대비 VI/d 배수·증감률, 11월 C/N 효과 중앙값, 동일 참여 집단 VI/d 변화
- 월별: 완료 VI·VI/d, 11월/해당 월 생산성 배수, 크롤링 VI·요청 수·비중, 참여 인원, 귀속 보완 VI
- 사례: 9·10·11월별 동일 리스팅 작업자의 크롤링/비크롤링 VI/d 개선 상위 5명. 각 방식 2기록일 이상, 양쪽 VI/d 양수, 배수 >1인 사례만 표시. 표본 d와 월별 개선/유효 인원 수를 함께 표시
- 비용·투입: 1,000 VI당 리스팅 d, 크롤링 관측 d, 중복 제거한 총 관측 d, 복원 가능한 월의 합산 VI/d, 홀드 제외 처리기간

상위 5명은 개선 예시이며 전체 평균이나 전체 효과를 뜻하지 않습니다. 같은 날 두 방식을 섞은 작업일은 C/N 비교에서 제외하므로, 혼합일을 포함하는 일반 분석의 배수와 다를 수 있습니다. 개인별 크롤링 제공자 비교나 Igoon/Oberon 간 순위는 만들지 않습니다.

실제 데이터의 결과가 좋을 것이라고 미리 정하지 않습니다. 숫자가 큰 항목은 배수·증감률로 강조하지만 기준 물량·d·표본을 함께 표시합니다. 9월은 부분 기간, 11월도 진행 중이므로 월 총량의 단순 증가율을 성과 향상으로 표시하지 않습니다. 허브 사용 필드·당시 난이도 기록은 없어 관측 변화 이상의 인과적 증명을 제공하지 않습니다.
