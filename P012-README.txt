Listing Update P012 — 백업 값의 자료형 보존
2026-10-07 / P011 적용 기준(B007)

교체 파일: archive_resume.gs 1개

현재 오류: 색상 문자열 "36" 등이 백업에서는 숫자36으로 읽혀 복사 후 검증 실패.
해결: 문자열/숫자/불리언/날짜를 Sheets API의 명시적 값 형식으로 기록. 비교 검사는 그대로 유지.
Task 신규복사/기존복사행 수정/누락행 삽입, REQUESTS 및 WORK_SESSIONS COPY 경로에 적용.
기존 COPY 작업은 현재 시트의 검증 위치를 처음부터 다시 확인하고 묶음을100행으로 회복. 실행 전체 초기화는 하지 않음.

실행 순서
1. continueArchiveV2 트리거가 있으면 삭제합니다. NEEDS_ATTENTION으로 이미 삭제돼 있으면 그대로 둡니다.
2. 실행 화면에서 백업이 실행 중이 아닌지 확인합니다.
3. archive_resume.gs 내용을 같은 이름 파일에 전체 교체하고 저장합니다.
4. 기존 일일 백업 설치 계정으로 runArchiveNowV1() 한 번 실행합니다.
5. ARCHIVE_PROGRESS의 Copy Cursor와 상태를 확인합니다. 현재 요청의 COPY가 통과한 뒤 다른 단계로 넘어가는지 봅니다.

하지 않을 것
- resetArchiveRunOnce 실행하지 마세요.
- 기존100행/백업 시트/원본245행/ARCHIVE_PROGRESS/DocumentProperties 삭제하지 마세요.
- 색상/가격/날짜를 수기로 덮어쓰지 마세요.
- setupSystem/기존 일일 백업/배정 트리거 재설치 불필요.
- 진단용 archive_copy_check.gs는 그대로 두어도 됩니다. 자동 실행되지 않습니다.

기존100행은 원본 고유키로 찾아 올바른 자료형으로 갱신합니다. 나머지145행은 이어서 복사합니다.
수정된 데이터를 다시 읽어 원본과 동일한지 검증하고, 검증 전에는 원본 삭제 단계로 넘어가지 않습니다.
새 API 쓰기는 대상 백업파일 시간대를 사용해 날짜를 저장합니다. 문자열은 텍스트 형식, 숫자는 숫자 형식을 명시합니다.
백업 표시 서식은 원본과 완전히 같지 않을 수 있으나 값과 자료형을 보존하는 것이 목적입니다.
이 패치는 사용자가 확인한 색상 자료형 오류를 대상으로 합니다. 다른 데이터 불일치까지 무시하거나 자동 건너뛰지 않습니다.

검증
원본245행/숫자로 변한 기존백업100행/저장된 chunk1 상태 복구 테스트 통과.
문자열36/49/57, 앞자리0, 긴 숫자 문자열, =시작 문자열, 쉼표 문자열, 실제 숫자/불리언/공백 확인.
원본 직접 변경 없음. 테스트는 로컬 모의 API이며 회사 운영함수를 대신 실행하지 않았습니다.
