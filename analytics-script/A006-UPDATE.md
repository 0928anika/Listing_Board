# A006 — 환산 근무일 생산성·투입 계획·홀드 보정

## 적용

분석 파일의 Apps Script에서 `Code.gs`, `Layout.gs`를 각각 전체 교체하고 `refreshListingAnalytics`를 일반 실행합니다. CONFIG의 A006과 최종 성공 시각을 확인합니다. 운영 코드·매니페스트·기존 트리거를 교체하거나 setup을 다시 실행할 필요는 없습니다.

## 대표 지표

**환산 근무일당 완료 VI = 순증 완료 VI / sum(작업자 고유 기록일 × CONFIG G:H 근무비율)**

- 0.5 근무자 10기록일은 5환산인일입니다. 비율 미설정은 1입니다. 비율 변경은 전체 과거에 소급합니다.
- 월별·주별·작업자·일별·외부 지원·Node·내외부 비교 탭 상단에 대표 표를 제공합니다. 원래 VI/h 및 시간 기반 순위는 `참고`로 표시합니다.
- 2P·3P 공통 대표 표는 같은 작업자·날짜를 한 번만 셉니다. 2P와 3P 각각의 VI도 공통 환산인일로 나눕니다. 서로 다른 범위/Node의 인일은 중복될 수 있으므로 단순 합산하지 않습니다.
- VI가 유효한 완료/일시정지 기록은 시간이 0·누락이어도 대표 실적과 기록일에 포함됩니다. ACTIVE·VI/날짜 누락은 등록 지표에서 제외합니다. 시간은 참고 지표에만 사용합니다.
- 외부 인력도 같은 공식으로 별도 표시합니다. 실제 등록 참여비율에 맞게 CONFIG를 입력해야 하며, 등록 참여시간을 모르는 사람의 기본 1은 정확한 전담 인일을 뜻하지 않습니다. 내부와의 단순 순위 비교를 피합니다.
- 기록일은 출근일이 아닙니다. 아무 기록도 없는 날은 분모에 들어가지 않아 실제 근무 전체의 생산성과 다를 수 있습니다.

## 크롤링과 등록 연결

`크롤링 효과` 탭에 월별 작업자 크롤링 VI·환산인일·VI/환산인일과 같은 요청들의 현재 3P 등록 누계를 표시합니다.

- 크롤링 분류는 현재 `CRAWL_COMPLETED`만 사용하며, 비크롤링은 `N/A`, 나머지는 확인 불가입니다.
- 완료일이 불완전하므로 완료 요청의 현재 Total VI를 그 작업자의 **마지막 CRAWL 기록월**로 추정 귀속합니다. 월을 넘긴 작업의 VI를 나누지 않습니다. 연결 날짜가 없으면 `시점 미확인`입니다.
- 크롤링 날짜는 세션 종료일, 없으면 시작일입니다. 같은 날 여러 요청을 해도 작업자당 하루입니다. 진행 중 CRAWL의 날짜도 분모에 포함합니다.
- 연결 3P VI는 같은 요청의 현재 누계로, 그 크롤링월에 등록됐다는 뜻이 아닙니다. 크롤링 물량은 현재 Total VI이므로 최초 제출량과 다를 수 있습니다.
- 크롤링/비크롤링 등록 비교는 각각 해당 분류의 3P 기록일 기준입니다. 같은 사람·날짜가 양쪽에 나타날 수 있으므로 분류별 인일을 합산하지 않습니다.
- 기존 백업은 CRAWL을 장기 집계에 보존하지 않습니다. 관측 속도가 과대평가될 수 있으므로 기록 연결 상태와 기준 속도를 확인합니다.

## 투입 계획

새 `투입 계획 설정` 탭은 입력용이며 다음 새로고침에도 값을 유지합니다. 입력 후 다시 새로고침하면 `투입 계획`에 반영됩니다.

- 기준 월: YYYY-MM
- 크롤링/등록 환산 인원: 전일 전담 인원으로 환산한 각 역할 인원. 예: 0.5 근무자 2명은 1명. 같은 사람을 양쪽 전담 인원으로 중복 배정하지 않습니다.
- 목표 작업일
- 필요하면 미확정 요청당 예상 VI, 크롤링·등록 VI/환산인일 기준 속도 보정값

크롤링 속도 C, 크롤링 후 등록 속도 L일 때 표준 1,000 VI에 `1000/C + 1000/L` 환산인일이 필요합니다. 합산 속도는 `1 / (1/C + 1/L)`입니다. 비크롤링 등록 속도로 같은 물량의 인일을 구해 추정 절감인일·효율 배수를 비교합니다.

각 역할의 하루 용량은 `속도 × 환산 인원`, 직렬 공정 용량은 두 단계 중 작은 값입니다. 현재 잔량의 단계별 필요 인일, 지정 인원에 따른 작업일, 목표 작업일 내 필요 환산 인원 및 전일 전담 인원 올림값을 표시합니다.

예측은 **현재 잔량의 3P 등록까지**이며 2P 완료 납기가 아닙니다. DONE/DROP/취소·2P 전용은 제외합니다. ON HOLD는 별도 잔량으로 표시하고 재개 전 예측에서 제외합니다. 미확정 크롤링 VI는 요청당 표본 평균/입력값으로 추정하고 확정 물량과 구분합니다. 분류/물량 확인 필요 요청도 예측에서 제외합니다.

신규 유입·휴일·승인대기·재작업·요청별 분할 제약은 모델에 없습니다. 병행 작업일은 용량상 이상적 하한이고 순차일도 납기 보장이 아닙니다. 준비·등록 인일 합산은 같은 사람이 같은 날 두 작업을 한 기록의 실제 노동량이 아닌, 두 역할을 분리한 계획 시나리오입니다.

## 홀드 보정 처리기간

월별 및 Node별 대표 표에 **전체 경과일, 기록 홀드일, 홀드 제외 경과일**의 중앙값과 유효 표본 수를 표시합니다.

`홀드 제외 경과시간 = Completed At − Requested At − Blocked Time (Hours)`

완료 요청만 사용합니다. 홀드 누락·음수·전체시간 초과는 0으로 추정하지 않고 보정 표본에서 제외합니다. 세 중앙값은 동일한 유효 요청들에서 각각 계산합니다. 홀드 사유를 모르므로 전부 외부 요인이라고 단정하지 않습니다. 단위는 달력일이며 작업시간이나 SLA 위반일수가 아닙니다. 기존 전체 리드타임은 남겨둡니다.

실제 회사 데이터는 사용자가 실행해 확인합니다. 코드 검증은 합성 집계 및 출력/설정 모의 실행 기준입니다.
