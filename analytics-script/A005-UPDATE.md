# A005 — 크롤링 효과 및 개인별 크롤링 일평균

## 기존 분석 파일 업데이트

1. 분석 스프레드시트에 연결된 Apps Script를 엽니다.
2. `Code.gs`와 `Layout.gs`를 교체본 브랜치의 파일 내용으로 각각 전체 교체하고 저장합니다.
3. 일반 실행으로 `refreshListingAnalytics`를 실행합니다.
4. `CONFIG`의 버전 `A005`, 최종 성공 시각, 새 `크롤링 효과` 탭을 확인합니다.

운영 스프레드시트 코드 교체, setup 실행, 매니페스트 교체, 기존 CONFIG 변경 및 트리거 재설치는 필요하지 않습니다. 분석만 수행하며 운영 데이터를 쓰지 않습니다.

## 등록 생산성 비교

- 현재 REQUESTS `크롤링 단계`를 공백·대소문자 정규화합니다. `CRAWL_COMPLETED`는 크롤링, `N/A`는 비크롤링, 그 밖은 확인 불가입니다.
- 크롤링 완료일, 필요 체크박스, 최초 요청 유형은 분류에 사용하지 않습니다. 현재 단계를 과거 작업에 소급하므로 당시 상태를 복원한 결과가 아닙니다.
- 내부 3P만 대상으로 합니다. CONFIG 외부 지원 작업자, 2P, CRAWL 준비시간은 제외합니다.
- 생산성은 작업시간이 양수인 기록의 순증 VI 합계 / 같은 기록의 작업시간 합계입니다. 0시간 VI는 물량 비중에만 포함하며 별도 열로 표시합니다. 음수 정정은 유지합니다.
- 월별·일별 비중, 일별 및 최근 7개 달력일 합산 생산성, 월별 같은 작업자·같은 Node 비교, 확인 불가 사유를 제공합니다. 배수는 두 그룹 생산성이 모두 양수일 때만 계산합니다.
- 전체 비중과 분류 확인 내 비중을 따로 표시합니다. 그룹 순증 VI가 음수이거나 분모가 0이면 비중은 공란입니다. 일별 표에는 기록이 있는 날짜만 나옵니다.
- 양쪽 작업시간·VI·요청 수를 함께 확인하세요. 같은 작업자/Node 비교도 난이도·브랜드·시기 차이가 남는 관찰 비교입니다. 인과 효과나 준비시간 포함 팀 전체 생산성을 뜻하지 않습니다.

## 크롤링 작업자 개인별 1일 평균

- 분자: `CRAWL_COMPLETED` 요청의 현재 `Total VI`를 현재 `크롤링 작업자`에게 요청당 한 번 합산합니다. 세션 수만큼 중복 합산하지 않습니다.
- 분모: 같은 작업자의 WORK_SESSIONS `Stage=CRAWL` 기록의 종료일, 종료일이 없으면 시작일을 KST 날짜로 계산한 고유 일수입니다. 시간은 사용하지 않으며 0시간/ACTIVE 및 진행 중 요청의 작업일도 포함합니다. 미래 날짜는 제외합니다.
- 크롤링 완료일을 신뢰할 수 없으므로 개인 평균은 전체 보유 기록 기준으로 제공합니다. 일별 제출 VI 및 월별 개인 제출 평균은 추정하지 않습니다.
- 완료 요청과 작업자의 CRAWL 날짜 기록이 모두 연결되고 VI가 유효할 때 `총 VI/기록일`을 표시합니다. 누락되면 전체 평균은 공란이고 `연결 VI/기록일(참고)`와 요청 기록 연결률, 누락 사유를 표시합니다.
- 현재 장기 집계 코드는 CRAWL을 보존하지 않습니다. 따라서 백업된 작업일이 빠질 수 있고, 연결률 100%도 일부 날짜 누락을 보증하지 않습니다. 평균은 출근일·8시간 환산 생산성이 아닌 현재 보유 CRAWL 기록일 기준 참고 수치입니다. 현재 Total VI 역시 제출 당시 물량과 달라졌을 수 있습니다.

## 실제 데이터 확인

새 탭의 표본 수, 0시간 실적, 확인 불가 사유, 크롤링 작업자 누락 점검을 먼저 확인하세요. 갱신 중 실패하면 일부 결과 탭만 바뀔 수 있으므로 CONFIG 최종 성공 시각을 기준으로 사용합니다. 실제 회사 데이터 실행은 사용자가 수행하며, 이 업데이트에서는 로컬 합성 데이터 검증만 했습니다.
