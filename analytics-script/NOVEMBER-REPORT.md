# 11월 보고 — 주차별 비교·전체 C/N·통합 VI/d

기존 분석 Apps Script의 LeadershipReport.gs만 전체 교체하고 **buildNovemberReport**를 실행합니다. 일반 refreshListingAnalytics 및 운영 코드는 변경하지 않습니다. 이전 실행 함수도 같은 함수를 호출합니다.

## 1. 월별 통합 생산성

- 리스팅 VI/d: 리스팅 완료 VI / 리스팅 d
- **크롤링+리스팅 통합 VI/d: 리스팅 완료 VI / 크롤링+리스팅 총 d**

크롤링 세션이 없으면 Started At 월에 요청당 1일×크롤링 작업자의 CONFIG 근무비율을 더합니다. 0.5 근무자는 0.5d입니다. 관측 세션은 사람·날짜를 중복 제거하고, 요청별 가정 d는 추가합니다. 화면에는 합산 총 d만 표시하며 실제 작업시간이 아닌 계획 기준입니다.

## 2. N VI/d · C VI/d · 배수

- N VI/d: 해당 작업자·해당 월의 비크롤링 완료 VI / 비크롤링 기록일의 보정 d
- C VI/d: 해당 작업자·해당 월의 크롤링 완료 VI / 크롤링 기록일의 보정 d
- 배수: C VI/d / N VI/d

**양쪽 유형이 각각 2개 이상의 고유 기록 날짜를 가져야 비교에 포함합니다.** 보정 후 2d가 아니라 기록 날짜 2일입니다. 0.5 근무자도 각 유형 2기록일이면 포함됩니다. 같은 날 두 방식이 섞인 작업일은 비교에서 제외합니다.

한쪽 날짜가 1일뿐인 고배수도 제외합니다. 특정 이름을 제외하는 규칙은 없습니다. 조건을 통과한 개선 사례를 배수 순으로 최대 5명 표시하고, 부족해도 전월비·참고 사례로 채우지 않습니다.

표 아래에는 전체 C VI/d, 전체 N VI/d 두 값만 표시합니다. TOP 5가 아닌 같은 2일 기준을 통과한 전체 비교 대상자의 C VI 합계/C d 합계, N VI 합계/N d 합계입니다. 개선 배수가 1 이하인 비교 대상자도 전체 합계에는 포함됩니다. 개인별 평균이나 중앙값은 아닙니다.

## 3. 크롤링 없는 경우의 필요 d

평균 요청 VI는 해당 월 작업한 고유 요청의 현재 Total VI 평균이며 표본 수를 표시합니다.

- **크롤링 없이 리스팅 · 요청 1개 필요 d = 평균 요청 VI / 2번 전체 N VI/d**
- 크롤링+리스팅 · 요청 1개 필요 d = 평균 요청 VI / 1번 통합 VI/d
- 요청 5개·10개는 해당 월 요청 1개 d의 5배·10배
- 동일 크기 비교는 11월 평균 VI와 같은 크기를 각 월 속도로 처리할 d

따라서 크롤링 없는 비교 속도는 2번과 동일합니다. 유효 N 비교 기록이 없으면 다른 유형의 속도를 대신 넣지 않고 비교 기록 없음으로 표시합니다. 실제 요청별 경과기간 평균이 아니라, 월별 기록과 현재 요청 크기에 근거한 계획값입니다. 일부 속성/VI 누락 때문에 월 전체를 차단하지 않고 계산 가능한 기록으로 집계하며 누락 수를 표시합니다.

각 주의 전체 리스팅 작업 요청 수, 크롤링 요청 수·비중, 완료 VI, d, VI/d를 표시합니다. 같은 요청이 여러 날짜·여러 작업자에게 있어도 주 안에서는 한 번만 세며, 다른 주에 다시 작업하면 그 주에도 포함합니다.

요청 비중은 해당 주 3P 작업기록이 있는 고유 요청 중 현재 CRAWL_COMPLETED인 요청 건수 비중입니다. 월별 VI 비중과 분모가 다릅니다. 주간 VI/d는 주간 VI 합계/주간 d 합계로 계산하며 일별 VI/d의 평균이 아닙니다. 일별 표와 7일 이동 VI/d는 제거했습니다.
